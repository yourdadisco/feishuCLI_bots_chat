### 1.2 架构设计原则
1. **无状态设计**：服务器不持久化存储状态，事件驱动的纯函数式处理
2. **去中心化**：三个 Bot 各自独立凭证，互不影响
3. **降级优先**：LLM 调用失败有预设 fallback 回复，不中断流程
4. **安全隔离**：API Key 仅通过环境变量注入，代码中无硬编码
5. **零外部依赖**：纯 Node.js 原生 API，无 npm 包依赖

## 3. 核心模块设计

### 3.1 Webhook 事件接收模块

**文件**: `server.js` — 主入口

```
POST / → 事件处理
GET  / → 健康检查
```

**事件处理流程**:
```javascript
收到 POST 请求
  │
  ├─ body.challenge 存在?
  │     └─ 返回 { challenge: body.challenge }  // URL验证
  │
  └─ body.header.event_type === 'im.message.receive_v1'?
        │
        ├─ event.chat_type === 'group'?
        │    └─ 群聊消息
        ├─ event.sender.sender_type !== 'app'?
        │    └─ 用户消息（非Bot）
        │
        └─ 启动异步处理: runTeam(messageText)
              └─ 立即返回 200，不等待处理完成
```

**关键代码** (`server.js`):
```javascript
const server = http.createServer(async (req, res) => {
  let body = '';
  req.on('data', chunk => body += chunk);
  req.on('end', async () => {
    const data = JSON.parse(body);
    // 挑战验证
    if (data.challenge) return res.end(JSON.stringify({ challenge: data.challenge }));
    // 消息事件
    if (data.header?.event_type === 'im.message.receive_v1') {
      const chatType = ev.chat_type || ev.message?.chat_type;
      if (chatType === 'group') {
        runTeam(text).catch(e => console.error(e));
      }
    }
    res.end(JSON.stringify({ ok: true }));
  });
});
```

### 3.2 团队讨论编排模块

**核心流程**：固定 5 步顺序执行，每步调用 LLM 后发消息到群聊

```
runTeam(task)
  │
  ├─ Step 1: 产品总监开场
  │     System: 总监人设
  │     User: "用户任务：{task}。现在产品总监发言。@产品经理做产品分析。"
  │     → sendMsg(总监Bot, 回复)
  │
  ├─ Step 2: 产品经理分析
  │     System: 产品经理人设
  │     User: "用户任务：{task}。讨论历史...。现在产品经理发言。做产品分析。"
  │     → sendMsg(产品经理Bot, 回复)
  │
  ├─ Step 3: 产品总监指派研发
  │     System: 总监人设
  │     User: "讨论历史...。现在产品总监发言。@研发做技术评估。"
  │     → sendMsg(总监Bot, 回复)
  │
  ├─ Step 4: 研发工程师评估
  │     System: 研发人设
  │     User: "用户任务：{task}。讨论历史...。现在研发发言。做技术评估。"
  │     → sendMsg(研发Bot, 回复)
  │
  └─ Step 5: 产品总监总结
        System: 总监人设
        User: "讨论历史...。现在产品总监发言。给出完整总结。"
        → sendMsg(总监Bot, 最终总结)
```

**关键设计**：
- 每步间隔 3 秒，模拟真人思考节奏
- 历史上下文通过 `history.slice(-20).join('\n')` 传递
- `max_tokens: 3000` 确保长文本输出
- 消息超过 2000 字自动分段发送

### 3.3 LLM 集成模块

```javascript
async function askAI(systemPrompt, context, name, task) {
  const userPrompt = `用户任务：${task}\n\n${context}\n\n现在${name}发言。`;
  const response = await fetch('https://api.deepseek.com/v1/chat/completions', {
    method: 'POST',
    headers: { Authorization: `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'deepseek-chat',
      messages: [
        { role: 'system', content: systemPrompt },
        { role: 'user', content: userPrompt },
      ],
      temperature: 0.85,
      max_tokens: 3000,
    }),
  });
  return (await response.json()).choices?.[0]?.message?.content?.trim() || '';
}
```

**System Prompt 设计**（三个角色的差异化）：

| 角色 | System Prompt 要点 |
|------|-------------------|
| 产品总监 | 调度者角色，负责 @人 指派任务、总结决策 |
| 产品经理 | 以 `@产品总监` 开头，分析需求/市场，用表情 |
| 研发 | 以 `@产品总监` 开头，评估可行性/成本，不用表情 |

### 3.4 飞书 API 集成模块

**Token 管理**：
```javascript
async function getToken(cfg) {
  const r = await fetch('https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ app_id: cfg.id, app_secret: cfg.secret }),
  });
  return (await r.json()).tenant_access_token;
}
```

**消息发送**（含分段逻辑）：
```javascript
async function sendMsg(cfg, text) {
  const token = await getToken(cfg);
  const MAX = 2000; // 每段最大字数
  const parts = [];
  for (let i = 0; i < text.length; i += MAX) {
    parts.push(text.substring(i, i + MAX));
  }
  for (const part of parts) {
    await fetch('https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id', {
      method: 'POST',
      headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({
        receive_id: CFG.chatId, msg_type: 'text',
        content: JSON.stringify({ text: part }),
      }),
    });
  }
}
```

## 6. 安全设计

### 6.1 API 密钥管理
- 所有密钥通过 **Zeabur Environment Variables** 注入
- 代码中 `process.env.XXX` 读取，无硬编码
- 三个 Bot 使用独立凭证，互不依赖
- 日志中不输出密钥内容

### 6.2 事件验证
- 飞书事件订阅包含 URL 挑战验证机制
- 服务器正确响应 `challenge` 后才能接收事件
- 可选择验证事件 `token` 字段防止伪造（当前简化处理）

### 6.3 消息安全
- 用户消息仅用于本次讨论上下文，不持久化
- 超过 20 轮的历史自动丢弃（滑动窗口）
- 所有消息通过 HTTPS 传输

## 7. 数据处理流程

### 7.1 消息流
```
飞书事件推送 → HTTP Server → JSON解析
  → 提取 chat_type, sender_type, content
  → 验证群聊非Bot消息
  → 异步启动 runTeam()
  → 返回 200 OK
```

### 7.2 LLM 调用流
```
runTeam(task)
  → 构建 System Prompt + 用户 Prompt
  → fetch DeepSeek API
  → 解析 response.choices[0].message.content
  → 清理首尾特殊字符
  → 返回纯文本回复
```

### 7.3 消息发送流
```
LLM回复
  → 检查长度 > 2000? → 分段
  → 获取对应 Bot 的 tenant_access_token
  → POST 飞书消息 API
  → 失败则写日志但不影响后续步骤
```

## 8. 错误处理

### 8.1 LLM 调用降级
| 错误场景 | 处理方式 |
|----------|----------|
| API 超时 | 使用 fallback 预设回复 |
| API 返回空 | 使用 fallback 预设回复 |
| API 格式错误 | catch 异常，使用 fallback |
| 网络错误 | catch 异常，使用 fallback |

每个步骤都有 fallback 回复，确保流程不会卡死：
```javascript
const msg = await askAI(...) || fallbackText;
```

### 8.2 飞书 API 错误
- Token 获取失败 → 跳过该步骤，不影响后续
- 消息发送失败 → 写错误日志，继续下一步
- 不重试（保证响应速度）

### 8.3 消息去重
```javascript
const processed = new Set();
if (processed.has(msgId)) return; // 已处理过则跳过
processed.add(msgId);
```

## 11. 风险评估与应对

### 技术风险
| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| DeepSeek API 不稳定 | 中 | 高 | Fallback 回复，不中断流程 |
| 飞书事件推送延迟 | 低 | 中 | 异步处理，不影响用户体验 |
| Zeabur 服务宕机 | 低 | 高 | 快速重新部署，代码在 GitHub |
| LLM 输出质量不佳 | 中 | 中 | 优化 System Prompt，多Agent互相校验 |
| API Key 过期 | 低 | 高 | 环境变量更新，重新部署 |

### 项目风险
| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 用户误用导致循环触发 | 低 | 中 | 消息去重机制防止重复处理 |
| 长文本超出飞书限制 | 中 | 低 | 分段发送机制自动处理 |
| 群聊消息过多 | 低 | 低 | 每轮固定5步，不会无限循环 |
